# CRE simulation status

The two workflows compile to WASM through the CRE CLI. Local simulation of a **confidential**
workflow currently traps inside the engine, and the trap reproduces on Chainlink's own unmodified
scaffold, so it is upstream rather than something in this project.

## What succeeds

```
Loading settings...
Checking RPC connectivity...
Compiling workflow...
✓ Workflow compiled
✓ Simulation limits enabled
  Binary hash: 437e8b9e1ae64c62e861ca8b880e99810f01acb2063cc6775725756472c3c2dd
  Config hash: 2d6a3a1213e8ac2c87f5fab80c743c7f530eca128ee8e417bcd96bbd601b08a8
```

The CLI authenticates, loads project settings, checks RPC connectivity, typechecks the TypeScript,
compiles to WASM, applies production limits, and produces binary and config hashes. Secrets resolve
from `secrets.yaml` through the environment - removing `.env` changes the failure to a clean
`environment variable ... not found`, which confirms the secrets path works.

## Where it stops

```
Failed to create engine: failed to execute subscribe: error while executing at wasm backtrace:
    0:  0x9a097 - <unknown>!<wasm function 313>
    1:  0xdb47f - <unknown>!<wasm function 1231>
Caused by:
    wasm trap: wasm `unreachable` instruction executed
```

## Why this is upstream, not ours

Rather than assume, this was isolated:

| Test | Result |
|---|---|
| Our workflow, CLI v1.32.0, SDK 1.18.0 | traps |
| Our workflow, CLI v1.32.0, SDK 1.19.1 | traps, different binary hash |
| Our workflow, CLI v1.26.0 (the version the docs recommend) | traps |
| **Chainlink's own scaffold from `cre init`, untouched** | **traps, identically** |
| Same scaffold with `.env` removed | fails earlier and cleanly at the secrets step |

The last two rows are the argument. A project generated by the CLI itself, with no edits, reaches
the same trap at the same wasm offsets. The trap is in `subscribe`, which is where `handlerInTee`
registers, and it is reached only once secrets resolve - which is why the stock template appears to
"work" until you actually give it a secret.

The CLI also reports, on scaffolding a confidential template:

> Confidential Workflows is in private beta - enrollment via your Chainlink account team is
> required to deploy.

## What stands in its place

- `bun test` in each workflow: **25 tests**, covering both triggers and the report encoding, using
  the fake `TeeRuntime` pattern from the official template.
- `npm run protect` from the repo root: the same decision function over generated price paths,
  reporting whether it avoided liquidation, preserved the carry, and used emergency capital
  efficiently.
- Both workflows typecheck against the real `@chainlink/cre-sdk`.
